## 票 01：viewpoint 越權（IDOR）

| # | Codex 結論 | Claude 查證 | 採納 |
|---|---|---|---|
| 1 | 三條路由只掛 `IsLoggedIn` | `app/routes/router.go` `configureUserRoutes`：`/:id/viewpoint` 的 POST／GET／DELETE 在 `IsLoggedIn()` 之後、`IsSysAdm()` 之前 | 是 |
| 2 | 三個 handler 只用路徑 `:id`，從不讀登入者 | `app/controllers/viewPoints.go:16-35,42-55,61-80` | 是 |
| 3 | model 的刪除條件 `id = ? AND user_id = ?` 兩個值都來自網址，擋不住 | `app/models/viewPoints.go:48-53` | 是 |
| 4 | context 的 `accountID` 與 `auth_users.id` 同一個 ID 空間 | `controllers/auth.go` 用 `user.ID` 產 JWT；`middleware/auth.go` 把 `claims.AccountID` 設成 `accountID`；`models/user.go` `AuthUser.ID` 對應 `column:id` | 是 |
| 5 | 回應帶出 `AuthUser` 的 email／is_admin「看起來成立」 | **不採納**。`app/models` 全部沒有 `Preload`／`AfterFind`（`grep` 0 筆），`GetViewPointByUserID` 只 `Where(...).Find`，`AuthUser` 應為零值。證據 `probe-2.out` 第 7 行在 `"Auth` 處就被截斷，沒有顯示 email。 | 否（見下） |
| 6 | 嚴重度 S2 合理；限流（每分鐘 10,000 以上）不構成防護 | `global/consts.go:24-27` | 是 |

修法方向（採納 Codex）：
- 加一個共用的「本人」檢查（middleware 或 helper），比對 `:id` 和 `accountID`，不符回 403。三條路由都要。
- 預設只限本人，管理者也一樣。管理者若需要管理他人的 viewpoint，另開明確的管理路由，不要用通用的管理者例外。
- model 層加防護：刪除時的擁有者由登入身分決定，或檢查影響筆數。
- 先寫的失敗測試：user 3 對 `/user/2/viewpoint` 做 GET／POST／DELETE 都要 403；user 3 對自己的 `/user/3/viewpoint` 照常可用；管理者的行為依選定的政策寫測試。repo 目前只有 `app/services/**` 的標準 `testing` 單元測試，還沒有 controller／router 的測試慣例。

**要更正票 01 的地方**：「讀取回應的 `AuthUser` 帶出 admin 的 email 與 is_admin」證據不足，讀碼推論是不會帶出（零值）。越權讀、建、刪三項本身已經實測成立，S2 不變。修正時請順便決定回應要不要移除 `AuthUser` 欄位。

- 把 `/ai-summary/trigger` 和 `/ai-summary/status/:dag_run_id` 搬到掛了 `IsSysAdm()` 的子群組（或在註冊時直接帶 `middleware.IsSysAdm()`）。`GET /ai-summary` 是否維持公開，由實作者確認。

**要更正票 03 的地方**：
- 補上「全域 JWT middleware 不擋匿名」。
- 補上「前提是有設定 `AIRFLOW_SUMMARY_BASE_URL`」。
- 範圍擴大到 status 路由。
